# ADR-0001：局域网拓扑与信任边界

## 背景

BOB v1 服务于一个用户、一台 Android 手机和一台 Windows 电脑。目标是以最少步骤双向传输文字、图片和文件，而不是建立通用跨平台或互联网文件服务。

## 决策

### 网络拓扑

- Windows `BOB.exe` 是唯一 HTTPS/WSS 服务端。
- Android 是主动连接的客户端，不监听入站端口。
- Windows 通过 `_bob._tcp.local.` 广播 mDNS/DNS-SD 服务。
- Android 只发现一台服务时自动连接；多台时让用户选择；发现失败时允许手动输入 IP，并使用协议固定的默认端口。
- v1 一次只允许一条 Android 活动会话。第二条会话被明确拒绝，不替换现有会话。

### 通道职责

- HTTPS 负责文件和图片的流式上传与下载。
- WSS 负责文字、会话、传输提议、状态、进度、取消、校验结果和错误。
- WSS 不承载大文件二进制内容。
- Windows→Android 的内容保存在 Windows 待发队列中；Android 连接后通过 HTTPS 主动拉取。

### 进程模型

- Windows 使用一个 WPF 进程，同时承载 GUI、托盘、Kestrel、mDNS、队列和本地数据库。
- 关闭窗口只隐藏到托盘；显式选择“退出 BOB”才停止网络服务。
- 不安装 Windows Service，不随系统自动启动。
- Android 仅在界面可见或有正在进行的传输时维持连接；活动传输可使用前台服务完成锁屏后的工作。

### 信任边界

- v1 只支持用户自己的可信局域网。
- 不提供账号、配对码、验证码、客户端证书、手机身份认证或设备授权列表。
- Windows 首次运行生成并持久保存自签名证书与稳定 `serverId`。
- Android 对未知 `serverId` 执行一次无提示 TOFU，保存服务端证书 SHA-256 指纹；以后必须匹配。
- 证书变化时阻断连接，直到用户在 Android 设置中重置信任。
- TOFU 是服务端证书信任，不在产品文案中称为“设备绑定”。

## 原因

- 电脑更适合常驻监听，Android 主动连接可避开移动端入站端口和长期后台限制。
- HTTPS/WSS 可直接承载结构化状态、流式内容和双向事件，无需依赖开发者模式或完整远程 Shell。
- 单进程 WPF 降低安装、IPC、权限和调试成本，符合自用一期目标。
- mDNS 只解决地址变化；TOFU 解决后续连接的服务端连续性。

## 后果

### 正面

- 两端均可在同一 WSS 会话中发起用户层发送操作。
- 手机不需要开放端口，也不需要全天在线。
- 文件可流式传输，内存占用不随文件大小线性增长。
- Windows GUI、托盘和网络服务共享同一生命周期。

### 限制与风险

- 首次 TOFU 无法防御首次连接时的 mDNS 冒充或中间人攻击；可信局域网是明确前提。
- 未认证客户端位于同一网络时可以尝试连接；单会话限制不是身份认证。
- 访客网络、AP 隔离、组播过滤或 Windows 防火墙可能阻断发现或连接。
- Windows 自签名证书变化需要 Android 手动重置信任。
- Android 未打开时，Windows 只能排队，不能即时送达。

## 被否决的方案

- ADB USB/无线：面向调试，电脑主控，授权面过宽，手机主动发送体验差。
- SSH/SFTP：可用于原型，但文字、状态、自动发现、双向主动发送和 Android 后台仍需额外协议。
- Android 作为服务端：增加后台常驻、入站端口与移动网络生命周期复杂度。
- Windows Service + WPF 双进程：一期需要额外 IPC、安装和权限管理。
- WebRTC、云中继、VPN overlay：超出同一 Wi-Fi、自用、无云端的范围。
